# A 员工任务书：fetchstat 统计、费率与规则

先读 [共同交付规范](DELIVERY_CONTRACT.md) 和 [开发与验收](../README.md)。你负责外部环境的可比较序列，不负责公司财报、产品规格或商业报价。

## 目的与对象

让研究端知道某地区、某时期的电价、需量费、工资、价格指数和税费规则；支撑运营成本及变化跟踪。统计对象是**发布机构 + 系列 + 地域 + 单位/口径**，每期一个观测。不是把州平均工业电价当作某园区真实电费。

## 指标和口径

| 指标名 | 必须分清 | 缺失时 |
|---|---|---|
| electricity.industrial_price | 州/地区、工业用户、均价、月份、原单位 cents/kWh 或其它；不等于园区合同价 | 留缺口 |
| electricity.energy_tariff | 适用公用事业/费率号、电压、季节、峰谷、用量档、有效期间 | 费率表先交原件，不能凭不完整条件算总账 |
| electricity.demand_charge | kW/月或 kVA/月、峰值计费规则、最低账单 | 不和 kWh 单价直接相加 |
| labor.wage / construction.cost_index | 岗位/行业、地区、均值/中位数、基期及季调口径 | 保留原文定义，不强归一 |
| tax.rate / permit.rule | 法域、税种/法规编号、适用对象、起止时间、豁免条件 | 缺适用条件标待核，不算园区实际税负 |

水价可按同样方法追加，第一批不强求。电耗 MWh 是用量，不是电价、MW 容量或接入权，不能混在一个指标里。

## 首批来源与实际步骤

1. **EIA 工业电价**：[API 技术文档](https://www.eia.gov/opendata/documentation.php)。申请自己的 key，放私有环境变量；用 v2 `electricity/retail-sales/data/`，筛 industrial/州，按文档查询原生 facet，不在代码猜 sector 编码。选 Texas、Oregon、Georgia、Virginia、Ohio 五条州工业电价序列，每条取最近 12 个**已发布**月份。保存查询参数（去 key）、原始响应及分页信息，提取每行 period/state/sector/price/unit。
2. **BLS 电气相关岗位工资**：[开发文档](https://www.bls.gov/developers/)。选择一个明确岗位和地区的官方系列，交系列定义及最新公开期间；验证其确实提供该指标，不拿不相关 CPI 顶替工资。API 不覆盖的官方表格保存 CSV/XLSX 原件即可。
3. 第一批至少把这两个来源登记并验证；五条 × 十二期只是期望范围，来源缺期据实交，不补齐猜值。下一批再加一个真实公用事业费率表，先把能量费和需量费分开提取，不急着计算统一电价。

API 分页、日期过滤、条件请求和限速按源文档执行；保存响应原件。指标更新按月/季/年源日历抓，日任务只检查是否有新版本，不每天制造一条相同月度记录。每月复抓最近三期以发现修订，每季对长历史校验一次，覆盖期可配置。

## 存量资料怎么用

从授权清单找统计表、费率 PDF、县市规则，按来源和系列识别，不按文件名关键词直接写数。表头、地区、单位、脚注齐全的行先交；旧期数据可以立即补历史，但不能当今日现价。没有原 URL 的原件先交来源待补线索。

## 本队额外交还与验收

- `registry/metrics.json` 中登记系列 ID、单位、地域、频率、修订窗口。
- 首包有至少一条完整 12 期序列的人工核对表，含原始单位；不足 12 期说明原因。
- 用固定样例证明分页不漏、缺值不填零、原生修订保留旧值、同名异口径不合并。
- 报告“系列数、期间观测数、缺期数、来源修订数”，不能把同一文件拆 60 份算 60 个原件。
